# 格位合成 RPG：开发计划（新标题待定）

版本：1.2 · 更新：2026-10-23（JST） · 对应[产品需求](requirements.md) · 当前实现：v0.3 森林美术样板（M1-A/B），规则基线仍为 v0.2。

本计划从已有可玩 Demo 继续推进。**M1-A/B 已交付样板，M1-C、M2、M3 尚未实现**。样板完成情况、实机证据和限制见[本轮迭代](iteration-03-sample.md)；未勾选项仍是未来计划。

## 当前优先级 · 2026-10-23

用户要求保留格位构筑玩法，重新选择非背包设定与新标题，并以参考图中 **16-bit fantasy / tactical RPG** 的角色细节作为最低方向。旧 M1-A/B 的运行、布局与资源接口成果保留，但其 64×64 简化主角、森林旅人和皮革背包不是后续量产标准。当前游戏仍是旧主题样板，本轮视觉探索不代表换设定已实装。

**原 M1-C 的全量素材生产先让位于「选题 → 同题材三种主角变体 → 新角色/背景/UI/一战实机样板」。** 详细产物、风险和验收见[美术换设定计划](art-retheme-plan.md)，A–H 均为待选候选，不能擅自定案。新样板通过 [RV-01 至 RV-06](art-direction.md) 后，再扩展现有资产和推进教学、预览、撤销。

本轮不扩规则内容：6×4 放置、旋转、合成、方向协同、自动战斗不变，保持 12 / 5 / 7 / 5；稳定物品 ID、`EmberRun` / `EmberSave` 和旧存档兼容。M2 的新增装备、灼烧、敌人机制与后续交付预算不因新世界观提前。

- [x] UI 按输出窗口布局、中文文字原生绘制；像素资产使用约定尺寸和整数倍率，消除方图长条拉伸。
- [x] 先完成 1280×800 与 1440×960 的布局，检查 1920×1080；采用可伸缩容器或统一布局计算，不再散落固定点击坐标。

退出条件：同一输入 fixture 的背包、资源和战斗结果不变；现有检查无回归；能在两种主验收尺寸正确拖放和选奖励。

### M1-B：森林旅人技术样板（已交付，视觉目标已更新）

**对应 FR-13 / 14。**

以下勾选项记录 2026-10-22 的实际交付，保留复现价值；它们不证明新主角已达到用户 2026-10-23 提出的精细像素标准，也不意味着森林/皮革成为新设定。

- [x] 统一原创墨绿森林、旧铜金、象牙白、围巾橙的色板与左上光源。
- [x] 制作英雄和苔团的待机/攻击/受击/退场帧，接入脚底锚点和等比显示。
- [x] 制作短剑、盾、磨刀石的缩略图与真实占格图，不通过拉伸表达长度。
- [x] 做一套背包皮革边、商店卡、手记纸张与主按钮状态，控制装饰密度。
- [x] 调整森林背景的颗粒、地面和角色对比；定义场景层与角色层共享尺度。
- [x] 接入剑击、箭矢、恢复、反伤、合成五类反馈样例，效果只消费事件，不能驱动伤害。

交付：一个可运行的整装和战斗样板，实际截图/短录屏、色板和源图。**先在实机上验证尺寸、识别和节奏，再批量制作其他素材。**

退出条件：美术规格 VA-01 至 VA-06 在**当期样板资产范围**内通过（英雄、苔团、三件装备及五类反馈样例）；12 装备与全部角色的全量验收留到 M1-C。主角不被拉宽，长装备不变形，地面不漂浮；不看说明也能分辨剑击、弓箭、恢复、反伤。仍用 v0.2 的真实规则，火焰效果不得冒充尚未实装的灼烧。

### M1-R：新设定与精细像素样板（优先于 M1-C）

**对应 FR-13，NFR-03 / 05 / 06。** 详细分阶段清单见[换设定计划](art-retheme-plan.md)。

- [ ] 用户从 A–H 或明确组合方向中确认角色身份、构筑器具、场景气质和主色；正式名称可继续待定。
- [ ] 同一题材制作三种主角造型，用同一精细像素标准比较脸部、眼神、发型、衣甲与武器；不混入低细节小人或非像素成品候选。
- [ ] 定案大像素立绘与专用战斗静态帧；比较 96×128 / 128×160 源画布的实机显示，记录人物占高与清晰度，不能只加透明边距达标。
- [ ] 制作匹配背景、操作矩阵、商店/详情和三件基准物件的样板；格位仍为矩形 6×4，交互与规则结果保持。
- [ ] 接入主角和一种普通敌人的真实逐帧动作，在实际窗口验证一战、旋转、合成与协同；保留旧样板截图作为对照。
- [ ] 新视觉通过 RV-01 至 RV-06；记录源尺寸、主题色板、来源、占位资产、检查结果与日语日志，再恢复全量生产。

退出条件：人物的脸、发束、材质、成年比例与长武器在实际战斗画面中可读，角色、地面、背景和 UI 视觉一致；用户所选题材没有改变内容预算或存档。概念图只能帮助选题，不能代替运行截图和动画验收。

### M1-C：新样板通过后扩展资产与上手体验

**对应 FR-02 / 03 / 05 / 06 / 13。**

- [ ] 按通过的新样板扩展现有 12 装备的专用缩略图和占格图、7 个祝福的独立图标；物件名称与造型随题材映射，底层 ID 与占格不变。

- [ ] 完成按实际操作推进的可跳过教学，退出教学后可正常存档继续。
- [ ] 独立设置文件先保存教学已完成/已跳过标记，跨启动不强迫重复教学；允许从菜单重看。其余音量与显示设置在 M2-A 扩展，远征重开不清教学设置。

v0.3 不提前加入商店权重和锁定、灼烧、三种敌人技能或新增 4 件装备，避免同时改表现、经济和战斗。

## 5. M3 / v0.5：试玩、平衡、打包

**对应 FR-07 / 14 / 15，NFR-02 / 06。**

- [ ] 固定不少于 30 个种子，三条明确记录的购物策略分别跑完整流程；输出种子、策略、胜负、死亡关卡、战斗时长、剩余生命、金币与装备轨迹。
- [ ] 找出明显无效物品、唯一必选配方、无反制敌人和购买/出售套利；调一次只改变相关参数，记录前后差异。
- [ ] 邀请 3–5 位首次试玩者，记录首购/旋转/合成/协同理解/失败解释等实际行为，收集时长与困难点；没有外部试玩时明确记为未验收，不用自动脚本代替。
- [ ] 按观察调整教学、物品描述、战斗速度和难度；检查小窗口、长文本、弹层、音量与暂停行为。
- [ ] 以多声道/事件音色替代所有效果共用一个播放器的截断问题；补环境声与适度音乐，提供总音量和静音，保留素材来源。
- [ ] 制作 Windows 导出预设，排除 MCP、SDK、测试素材与文档缓存；在没有编辑器依赖的干净环境验证离线启动、存档和五战流程。
- [ ] 附操作、存档位置、版本、已知问题、许可与问题反馈方式，生成包校验值；上传仓库的发布资产，不把 `.tools` 或本机路径放入分发包。

退出条件：满足需求验收矩阵；没有阻塞流程或资源丢失缺陷；实际试玩问题有修复或明确记录；发布包、源码提交、日语记录和截图版本一致。

## 6. 验证与证据矩阵

| 范围 | 方式 | 保存证据 |
| --- | --- | --- |
| 规则/经济/背包 | `npm run game:test` 加相关边界用例 | 检查结果、固定种子和失败复现；当前 385 是 v0.2 历史基线 |
| UI 输入与暂停 | 实际输入路径 smoke + 鼠标实测 | 拖放/旋转/合成/撤销/模态/尺寸检查记录 |
| 美术 | 新 RV 样板、同一 fixture 前后截图 + 一段实际战斗片段 | 新版本目录记录尺寸与来源；不覆盖 v0.1/v0.2/v0.3-sample。概念稿另存 `docs/concepts/`，不作为实机 |
| 新状态与敌人 | 固定种子、时间边界、来源统计 | 灼烧/连击/护盾/蓄力的预告、触发和结算一致性 |
| 存档 | 合法旧档迁移、坏档/未来版本/写入失败 | 迁移前备份、字段一致性和不覆写保护 |
| 平衡 | 同种子三策略批量模拟 + 实际试玩 | 可复现 CSV/JSON、脚本版本、样本限制、观察记录 |
| 性能 | 开发机实测，记录硬件/分辨率/战速 | FPS/帧时间采样；不能只凭截图声称 60 FPS |
| 打包 | 无编辑器的 Windows 干净环境 | 包版本/校验值、启动与离线流程记录 |

功能变更运行相关检查；构建插件相关变更运行 `npm run godot:build`。当前 C# 构建有 3 项上游弃用 API 警告的历史记录，不将其写成零警告。只改文档时检查链接、格式与一致性，不重复运行与变更无关的游戏测试来增加数字。

| --- | --- |
| 资产量增加仍无统一风格 | M1-R 新实机样板作为批量制作前置；历史 M1-B 接口成果可复用，旧角色质量不作为新标准 |
| 新题材不知不觉扩大玩法 | 先做现有 12/5/7/5 视觉映射；星盘不改圆形格，工作台不加接线资源，水下不加游泳系统 |
| 精细大角色挤占操作区域 | 在三种目标窗口比较源帧与整数倍率；先调场景和留白，不压缩文字或拉伸人物 |
| UI 重构同时改变规则导致难定位 | M1 保持规则数据与数量；每个组件迁移后保留原输入 fixture |
| 三路线实际仍由同一万能套装支配 | 先看相同种子购物记录和敌人机制，再调收益；必要时减少新物品，保留明确取舍 |
| 缺货导致构筑无法形成 | 阶段权重与锁定改善规划；不保证每局都能拿到任意完整套装；用多种子验证 |
| 新档格式伤害老玩家 | 迁移前保留备份；失败不改原档；不能迁移时明确提示而非静默重开 |
| 动画延迟反过来改变模拟 | 伤害由规则时间决定；表现跟随事件和战速；暂停统一停表 |
| 一直扩系统导致 Demo 无法交付 | 固定 1 英雄/1 区域/5 战/16 装备预算；扩包、职业和宠物进入后续候选 |
| 小样本或脚本结果被夸大 | 记录样本、策略局限和未验证环境；不写虚构胜率、工时或用户反馈 |

## 9. 下一次开始开发时的首个任务

执行 **M1-R 的选题与主角比较**：先呈现 A–H 候选和配图，等待用户选择设定；然后只为选定题材制作三种主角造型及新实机样板。选题前可完善共同规格、资产接口与验证工具，不将任一候选自动写入正式游戏。新样板通过后才恢复 M1-C 的全量素材、渐进教学、详细数值、属性比较与整装撤销。继续保留 12 / 5 / 7 与五战规则；不要把灼烧、商店权重或敌人技能夹进视觉改造。

后续候选是多职业、宠物、扩包/暂存或分支节点。它们不属于 v0.5 的承诺范围，应根据试玩证据再选择。
