# 開発計画（仮題）

この文書は、以前の詳細計画を現在の優先順位に合わせて日本語で整理したものです。ユーザーの決定により、**魔法使いとその敵、道具、魔法、エフェクト、基本の遊びを先に改善**します。騎士の新規開発と C2 は後回しです。[要件](requirements.md) · [職業の設計](classes-and-builds.md) · [美術方針](art-direction.md)

## 現在の状態

- 魔法使いには七戦の遠征、16種類の配方、戦後の魔力残滓、素材の凝結、専用の自動保存があります。七戦目はボスです。旧五戦の保存と一戦版は維持しています。[七戦の記録](devlog/2026-11-10-mage-seven-battles.ja.md)
- 元素の組み合わせと三種類の使い魔契約があります。完全な召喚成長、奥術循環、職業ごとの三構成は未完成です。[風の使い魔](devlog/2026-11-10-mage-wind-familiar.ja.md)
- 法盾は攻撃を実際に軽減した時に表示します。敵の攻撃予告と飛行効果も追加しました。[敵の攻撃](devlog/2026-11-11-enemy-charge.ja.md)
- 魔法使いはユーザーが選んだ一枚の画像から待機一種、攻撃三種、防御三種を表示します。攻撃と防御はそれぞれ発動時に選び、施法中は攻撃姿勢を優先します。AnimationPlayer による発射時刻は変更していません。[動きの記録](devlog/2026-11-12-mage-seven-poses.ja.md)
- 遠征画面では開発用の予行演習や通常時の手動保存・読み込みを隠し、保存失敗時の再試行を表示します。開発テスト用の機能や従来の一戦版は維持しています。

## 次に進める順序

1. **遊びと難しさの確認**：通常の資源取得と報酬で七戦を遊び、初期資源、勝利後の選択、敵の強さ、ボスまでの成長を調整する。固定配置の自動テストに加え、人が遊んだ感想を記録する。
2. **魔法使いの選択肢**：元素、術式、支援、使い魔の組み合わせを分かりやすくし、配置の違いが戦いに表れるようにする。新しい配方や状態は実ルール、資源、表示と検証をまとめて実装する。
3. **動きと効果**：発射、命中、法盾、敵の攻撃予告の読みやすさを改善する。姿勢を新規生成する場合は手足、顔、杖、サイズを目視し、既存姿勢との切り替えと実機を検証する。
4. **画面と説明**：戦闘画面を見やすく保ち、道具、配方、残数、効果、戦闘結果を自然な日本語で伝える。内部 ID や開発用情報をプレイヤー向け画面に出さない。
5. **検証と記録**：関連する自動テストと実画面を確認し、日本語の開発ログに結果、問題、制限を記す。実際のゲーム画像、試験用の自動操作、コンセプト画像を区別する。

## 以前のマイルストーン

従来の計画は、C0 で職業ルールを試作し、C1 で二職業の一戦、美術と動きを確認し、C2 で各三構成と五戦、C3 で説明・調整・Windows 向け配布を進めるものでした。C0 と C1 の一部には実装と記録がありますが、完全な二職業・六構成の受け入れは終わっていません。C2 と騎士の作業は現時点で優先しません。[C0 の記録](iteration-c0-rules.md) · [C1 静止画](iteration-c1-static-art.md) · [C1 の動き](iteration-c1-motion.md)

森林版の12装備、5配方、7祝福、5戦と旧保存は互換性を保つための既存範囲であり、将来の六構成を満たす予算とは限りません。新しい職業や状態を作る際は資源の取得、消費、イベント、保存、移行を別に設計・検証します。

## 完了の確認

- 変更したルールに応じた検査を実行し、結果と未検証の範囲を明記する。
- 生成素材の手、顔、武器、端の欠け、人物の一貫性を確認し、ゲーム内でも見た目と配置を確認する。
- 実機画面は版ごとのフォルダーに保存し、古い画像を上書きしない。
- 旧データ、プレイヤーの保存、作業中の変更を保護する。
- 日本語の開発記録とブログを実際の実装に合わせ、確認した節目を指定されたリポジトリへ送る。
