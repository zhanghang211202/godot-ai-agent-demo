# 双职业像素人设：六案比较与评审

日期：2026-10-24（JST）。阶段：**C1 人设比较；用户已选 MA＋KA 外观基准，专用战斗素材待制作**。采用特征与武器适配见[已确认角色基准](character-baselines.md)。

本轮为魔法师与 H 圣匣近战骑士各准备三种外观方向，比较人物吸引力、职业轮廓和后续动作制作条件。选择范围已经是两个首发职业，不再从八种题材中只选一个世界。玩法目标仍见[职业与构筑设计](classes-and-builds.md)，视觉验收仍以[美术规格](art-direction.md)为准。

**三种外观方案不等于三种构筑流派。** 帽子、元素球、长枪、小盾或重刃是本轮造型比较变量，不表示召唤、盾反、连击等规则已经实现，也不决定每条路线必须换一套衣服。现有 [C0 双职业规则原型](iteration-c0-rules.md)与玩家存档保持原样。

## 1. 怎么看这轮材料

- [离线六案对照页](concepts/2026-10-24-characters/index.html)：比较完整轮廓、面部和整体配色。概念 PNG 可单独打开。
- 原生审稿场景入口：`npm run art:review`。它用于在 Godot 窗口中比较静态概念的缩放表现；具体操作与已验证窗口以该场景实际说明和本轮开发记录为准。
- 两栏都可选全部六案；`Tab` 切换当前栏，`← / →` 换案，`N` 切换最近邻/平滑采样，`B` 切换深浅观察底。面部是人工选定的源图区域，未生成独立头像；128/160/192px是原图非零alpha包围盒的显示高度，不是人物头脚的测量值。
- 以下六张 PNG 是**透明底角色概念稿**，不是战斗精灵表。面部局部、缩放或合成预览仍来自概念稿；没有因此新增专用像素动画。

本轮分清两种预览：网页中的概念细节比较，以及 Godot 中的静态缩放与占位比较。两者都能暴露轮廓问题，但都不能替代 **RV-03 的专用战斗帧、真实背景、地面锚点与实际战斗窗口验收**。生成图的文件尺寸不等于精灵的逻辑画布；将其缩到 96×128 或 128×160 不会自动产生合格的战斗 sprite。

## 2. 共同人设控制与像素目标

生成时，两个职业先各用成年女性的发色和眼色比较服装与器具，避免同时更换过多变量。用户随后明确选择**MA 月庭礼装＋KA 旌旗长枪**作为人设基准；保留两案的脸部方向、发型、衣装与器具识别，再进行生产所需的像素归纳。正式姓名与游戏标题尚未确定。

上述是生成时的控制目标；六张独立生成稿的脸型、神情和比例仍有漂移，不宣称已达成严格同人设。全部原图为1024×1536，实际alpha范围为0–254，含低alpha残留；[清单](concepts/2026-10-24-characters/manifest.json)分别记录非零与alpha≥128包围盒。它们有透明区域，但不作为已清理的生产素材。

共同最低方向来自用户参考的 **16-BIT FANTASY / TACTICAL RPG**：可辨认的脸和眼神、成组头发、衣甲层次、材料区别、完整持握和明确武器轮廓。需要检查实际图稿是否做到，不能仅凭提示词或文件大小判定通过。

| 部位 | 比较要点 | 后续战斗帧需要保住什么 |
| --- | --- | --- |
| 脸与眼神 | 脸朝向、眼睛、眉线和发际有区分；帽檐、刘海与光效不能完全遮脸 | 真实显示尺寸下的朝向、眼神与头发/皮肤分离 |
| 头发 | 外轮廓与主要发束分层，高光跟随体积，避免满头散点 | 留下可读主发束，不能靠任意缩图变成细碎噪点 |
| 衣甲材质 | 布靠褶皱、皮革靠厚边与接缝、金属靠硬边和有限亮点；按方案实际材质检查 | 各材料仍可区分，不要求每套服装强加全部材料 |
| 身体与姿态 | 肩腰腿有重心，手握器具的位置明确，脚底能够对齐地面 | 面向、持握、脚位和动作起势一致；成人风格化比例不变成简化小人 |
| 武器负形 | 杖、刃、盾、手臂、头发和衣摆之间留出空隙 | 灰度与纯剪影仍能读出武器类型和朝向 |
| 像素语言 | 有组织的像素簇、清楚阶梯边、有限材质色阶 | 重新设计逻辑像素，而不是把插画机械缩小或加像素滤镜 |

成人约 3.5–4.5 头身与 96×128 / 128×160 战斗画布是已有的**制作试验建议**，不是对参考图源分辨率的测量，也不是概念稿已经符合的事实。概念阶段比例若有差异，应在战斗静态帧阶段明确调整并记录。

## 3. 魔法师：同一人物的三种衣装方向

固定比较特征：成年女性、紫发、琥珀眼。共同配色为紫、靛蓝、象牙白与旧金；精确色值在选择后固定。希望脸部有亲近感与专注神情，漂亮但不靠巨大光效或复杂饰品遮挡人物。A 的月庭仅作当前背景探索方向，元素编织、召唤、循环都需要以后按实际规则设计表现。

| 编号与概念 | 轮廓与衣装 | 重点检查 | 动作制作风险 |
| --- | --- | --- | --- |
| **MA 月庭礼装** · [完整 PNG](concepts/2026-10-24-characters/mage-a-lunar.png) | 宽帽、长发与多层裙摆，古典魔女轮廓；法杖与旧金装饰建立纵向识别 | 帽下的眼神是否清楚；主发束与帽饰是否分开；层裙的布与金属饰件能否区分；杖与身体是否留空 | 宽帽、长发、层裙会增加动作遮挡与摆动工作。小尺寸时应删掉次要花纹，不能只扩大画布保留装饰 |
| **MB 巡游短装** · [完整 PNG](concepts/2026-10-24-characters/mage-b-wayfarer.png) | 编发、裤装和较短前衣摆；实图仍有长法杖与宽大披风 | 前衣摆更利落，但提示中的短杖未实现；下垂披风仍挤占轮廓，不能称完全轻装 | 需收束披挂、腰间书与器具。裤装让腿部较可读，但施法姿势仍须独立设计 |
| **MC 奥术战装** · [完整 PNG](concepts/2026-10-24-characters/mage-c-arcane.png) | 高马尾、短战装与更开放的手部空间，强调施法姿势和身体方向 | 手掌、手臂与元素之间是否留空；小装甲和布料的材质分界是否清楚；高马尾不与武器粘连 | 元素球只能辅助说明手势，不能长期遮脸、遮手。后续应先画无特效的完整姿势，再按规则事件叠加法术 |

三案希望比较的核心分别是经典幻想魅力、旅行者的简洁易读、主动施法的动作空间。它们不分别对应元素、召唤和循环；任何一个定案造型都应能承载三条玩法路线。

### 魔法师背景方向：月庭与天文回廊

未来一战背景可用月白石台、靛蓝拱廊、远处天文仪和少量紫藤建立身份。远景降低对比与纹理密度；人物站位附近避免柱线穿过脸、杖和手势。元素高光优先于环境装饰，同时通过形状与事件标签区别元素，不能只换发光颜色。

这只是待制作的背景简表，**本轮角色透明稿并不包含已完成的月庭战斗场景**。背包区域保持可读的 6×4 平面，装饰集中在外框；获取与编织内容以 C0 实际规则为准。

## 4. H 骑士：同一人物的三种近战轮廓

固定比较特征：成年女性、栗棕发、琥珀眼。共同配色为象牙白、旧金、绯红与炭灰；浅甲、深色内衬与红色织物共同分隔身体。脸部开放，主武器与持握点清楚；不使用遮脸头盔补足职业感。

| 编号与概念 | 轮廓与衣甲 | 重点检查 | 动作制作风险 |
| --- | --- | --- | --- |
| **KA 旌旗长枪** · [完整 PNG](concepts/2026-10-24-characters/knight-a-banner.png) | 高马尾、分段浅甲、短披与长枪，强调战术 RPG 的挺拔轮廓 | 枪杆与手臂是否分离；枪尖、马尾和披风的方向能否辨认；浅甲是否仍有体积而非整片白色 | 长枪扩大整张姿势范围，可能挤压人物有效像素。后续不能为了容纳枪尖把脸缩得过小；需要专门验证站位和攻击前伸 |
| **KB 轻甲先锋** · [完整 PNG](concepts/2026-10-24-characters/knight-b-vanguard.png) | 实图为高蓬发尾、厚肩甲、长剑与较大的鸢形盾；轻甲差异有限 | 生成稿未实现低束发与小盾，腿侧露肤也偏离实用全覆盖目标；继续减甲片、披挂和盾面积 | 盾会遮挡远侧手臂与躯干。后续需要重画覆盖与持握；外观有盾不表示盾反规则已实现 |
| **KC 遗物重刃** · [完整 PNG](concepts/2026-10-24-characters/knight-c-relic.png) | 双手重刃与更厚的分段护甲，强调遗物重量、蓄势与力量传递 | 双手是否真正握在武器上；肩腰腿能否支撑重刃；大刃、披风与腿之间是否留空 | 大刃易挡住脸和胸甲，重甲也易变成纹样噪声。后续先验证蓄势与挥斩的关键姿势，不以整张立绘位移代替攻击动作 |

三案比较挺拔、灵活与沉重的视觉重心，不等于长枪、剑盾、重刃三个职业已经可玩，也不强制与 K-01 / K-02 / K-03 一一绑定。若选择 KA 或 KB 作为人物基线，K-01 的重刃仍需另做真实持握和动作设计；不能把现有重刃规则悄悄改成枪或盾。

### 骑士背景方向：象牙圣堂与金色余烬

未来一战背景以断裂圣堂、象牙白石、远处彩窗和金色余烬组织空间，保留稳定、连续的站立地面。浅色甲与浅色建筑之间用深中景、局部影色和低噪点留白分离；彩窗高光不穿过脸、武器或伤害数字。主角周围不堆砌同样高对比的金色碎纹。

这是待制作的场景方向，**本轮没有以静态人物稿完成圣堂关卡**。遗物题材可进入背包边框与物件剪影，但占格、旋转、方向连接与合法落点仍保持共享交互语言。

## 5. 选择方法：看可读性与制作条件

先在同职业内比较，再把法师与骑士并排，判断两人是否属于同一套精细像素游戏。两人无需相同衣装、相同环境色，但脸部品质、像素边缘、材质处理和显示尺度需要一致。

建议按以下次序评审，不预先用主观分数决定胜负：

1. **完整轮廓**：第一眼最喜欢谁；不看名字能否分清施法者与近战者。
2. **脸、头发与材质**：放大查看眼神、发束、持握与衣甲；记录具体喜欢或需要改动的部位。
3. **缩小后的损失**：在网页和 Godot 静态审稿中查看哪些细节丢失、武器是否与躯干粘连；这是重画需求，不能标为已通过战斗验收。
4. **背景适配**：浅甲能否从石墙分离，紫发能否从月庭暗部跳出；在背景未制作前只列风险，不能给出实际通过结论。
5. **动作空间**：帽檐、马尾、裙摆、盾和长武器会遮住什么；能否给施法、蓄势、命中与受击保留清晰姿势。

本轮选择结果是**MA＋KA**，未要求跨案混搭。后续以这两套特征整理统一设定稿；比例、像素簇与动作需要重新设计，概念PNG不会直接切片成动画。

## 6. 实图观察与尚未通过的部分

- MA的帽、月杖和层裙识别明确，脸与发束可单独观察；裙边、首饰与飘发细节密集，缩到128px时大部分会合并。MB裤装与MC开放双手形成差异，但后两者同样保留很长的衣摆与发束。
- KA的长枪、红旗与浅甲有鲜明职业轮廓，枪尖接近画布上沿；含武器的总占高会压缩脸部在战斗窗口中的有效像素。KC的双手握剑较清楚，重刃与手臂也有分离空间，但长刃与厚披风仍使姿势范围很大。
- 大图的眼睛、分束头发与布/甲差异比旧64×64样板丰富，但实际身形偏修长，未按3.5–4.5头身验收。边缘像素簇、细碎金饰、色阶和透明边距都尚未按专用逻辑网格整理，不能凭生成稿宣称达到受控16-bit生产规格。
- 三档缩小观察暴露了饰纹噪点和脸部丢失；这说明需重画专用战斗帧，不是把平滑采样打开就能解决。当前无实际背景、接触阴影、动作关键帧或战斗信息遮挡证据，RV-02仅有比较材料，RV-03仍待实施。

网页及Godot审稿台均为本地开发工具。Godot从被`.gdignore`排除的`docs/`直接读原PNG；导出包不会自动包含这些概念图，`art:review`不作为可分发游戏功能。

## 7. 选定之后的实际制作

1. 将两份选择整理为统一人设表，固定脸、发色、关键饰件、衣甲材料、武器持握与基础色板。
2. **分别重画专用战斗静态帧**，比较 96×128 / 128×160 等候选画布，记录实际人物占高、头部像素、透明边距与脚底锚点。像素需要人工取舍，不直接缩图或切片冒充 sprite。
3. 制作月庭/天文回廊与圣堂/余烬各一段背景，接入真实布局，在 1280×800、1440×960、1920×1080 检查角色、地面、生命条、背包与文字的关系；按 RV-03 记录证据。
4. 静态样板通过后制作待机、施法或蓄势/攻击、受击、退场动作，并与现有真实战斗事件同步；动画不私自增加命中、伤害或资源。
5. 将各一条路线接成可玩的职业一战样板，再扩展剩余流派、物件美术与教学。两名角色各三条玩法仍分别按职业验收，不能由六张造型图替代。

本轮概念和静态审稿放在 `docs/concepts/`。以后真实运行截图继续进入新的不可变版本目录，标明审稿 fixture 或实际游戏；不覆盖旧森林、C0 或此前八案探索记录。完成情况、检查结果与限制由日语开发日志记录，不能把待选人设、未画背景或未测窗口提前写成已完成。
