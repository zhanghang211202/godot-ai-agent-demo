# CodexとGodot MCPを使って、AIとゲームを作ってみた

こんにちは。今回は、AIに自然な言葉でお願いしながら、ゲームを作ってみた話です。

きっかけは、装備を並べて合成し、自動戦闘に挑む『[Overgeared Hero（靠装勇者）](https://tatakingdom.tw/zh-TW/games/overgeared-hero)』でした。バックパックの中身をどう配置するかで戦い方が変わるのが面白く、「似た遊びをAIと一緒に作れないかな？」と思ったのが始まりです。

参考としてWikiとYouTubeのプレイ動画を調べました。動画は全編を見たのではなく、YouTubeのプレビュー画像を何枚か確認しています。分からない細かいルールは決めつけず、まずは遊べる小さなデモを目指しました。

![現在の戦前準備画面。Godot上で操作した記録](../devlog/screenshots/2026-11-11-player-ui-v1/preparation.png)

## 今回使ったもの

- **Codex**：要件や計画の整理、プログラムの作成、修正、テスト。
- **Godot**：ゲーム本体を動かすエンジン。今回は.NET版を使用。
- **[Godot MCP](https://github.com/IvanMurzak/Godot-MCP)**：CodexからGodotの状態やスクリプト、AnimationPlayerの内容を確認するための連携。
- **画像生成**：キャラクター、背景、敵、アイコンなどの候補作成。

.NET SDKやnpmの依存関係はプロジェクト内に置き、環境をできるだけ分けました。実装はCodexによるファイル編集も併用しており、すべての操作をMCP経由で行ったわけではありません。

## どのように作ったか

### 1. まずは一戦できる形にする

最初から大きなゲームを目指すと、何が動いていて何が未完成なのか分かりにくくなります。そこで、6×4の盤面にアイテムを置き、回転・合成して自動戦闘するところから作りました。

「置けない場所に落としたら素材を消費しない」といった条件も、言葉で伝えながら確認しています。実際、ドラッグ中に回転した見た目と、配置後の向きがずれる不具合が出たので、入力データの扱いを修正しました。

### 2. キャラクターと背景を決める

最初はバックパックそのものを使う設定でしたが、途中で「職業によって違う戦い方ができるゲームにしたい」と方向を変えました。最初の対象は魔術師です。装備を買うだけではなく、火・水・風の元素を集め、魔法を紡ぐ設定にしています。

主人公と背景は複数案を生成し、16ビット風のファンタジーRPGを目指して選びました。生成した絵はそのまま採用せず、手が二つあるか、杖が途中で切れていないか、ポーズによって人物が別人に見えないかを確認しています。

### 3. 魔法を組み合わせ、戦いを増やす

盤面では、元素を重ねて術式にしたり、結晶核を隣に置いて攻撃を強化したりできます。たとえば水と風は連続攻撃、結晶核と水は月蛾の使い魔につながります。勝利後は敵から得た魔力残滓を使い、次の素材を凝結できます。

今の遠征は七戦で、最後はボスです。複数の構成で実際に最後まで進めるテストも用意しました。ただ、テストを通ることと、遊んでいて面白いバランスであることは別なので、ここはまだ調整中です。

### 4. 動作とエフェクトを少しずつ直す

法師の動きにはGodotのAnimationPlayerを使っています。複数の術式が同時に発動する場合は、戦闘の計算を変えずに、見せる動作を一つ選びます。法盾が攻撃を軽減したときには、盾のエフェクトを表示するようにしました。

一方、動作は簡単ではありませんでした。生成した中間姿勢は顔や髪が前後の絵と違って見え、全身を傾ける試みも違和感があったため取りやめました。現在は余計な中間姿勢を挟まず、杖を構えた状態から発射姿勢へ切り替えています。まだ姿勢間のつながりは改善したいところです。

![現在の戦闘。Godot上で0.05秒ずつ進めて撮影](../devlog/screenshots/2026-11-11-player-ui-v1/battle.gif)

### 5. 遊びながら指示を具体的にする

画面を確認して「敵をもっと大きく」「下の盤面より戦闘画面を広く」「開発用の表示を減らして」と伝え、少しずつ直しました。最初の指示だけで思い通りのものができるというより、出てきた結果を見て、気になる場所を具体的に伝える作業の繰り返しでした。

Godot MCPでは、接続状態やスクリプトのエラーを確認し、AnimationPlayerのキーも読み取っています。実際に動かした画面やテスト結果は、後から確認できるよう[開発ログ](../devlog/)に残しました。

## 作ってみた感想

自然な言葉から、実際に動くゲームまで進められたのは面白い経験でした。作りながら設定を変えたり、「この絵の手がおかしい」「動きが不自然」と伝えてやり直したりできるのも、AIと一緒に進める良さだと思います。

その一方、絵がきれいでも動かすと違和感が出たり、テストに通っても難易度の感じ方までは分からなかったりします。今は法師を中心としたデモの段階で、アニメーションやバランスにはまだ改善の余地があります。

最近はAnthropicの**Claude Fable 5.2**でゲームを作る事例も話題になっています。Anthropicの開発者が短い指示からFPSを作ったと報告しており、[紹介記事](https://cellcog.ai/blog/fable-5-2-one-shot-game-cost/)によると約8時間、API価格換算で約550ドルだったそうです。これは発表者の報告で、今回のゲームにFable 5.2を使ったという話ではありません。

AIにどこまで任せられるのか、引き続き試しながらゲームを育てていきたいと思います。ソースコードは[GitHub](https://github.com/zhanghang211202/godot-ai-agent-demo)で公開しています。
