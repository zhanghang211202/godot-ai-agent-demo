# 2026-10-27：法盾が攻撃を受け止め、敵と魔法が増える

前段`be6e2db`を受けて、ユーザーから「魔法使いの護甲は被弾時に出る護盾らしく」「敵や魔法も増やしてほしい」と依頼がありました。今回は魔法使いの一戦を広げ、法盾、二体の敵、四つの新しい編織魔法を実装しました。入口は`npm run game:mage`です。

![実機の鏡翼の蛾と魔法使い。固定24FPS、戦闘部分を原寸で切り出した無声6秒](screenshots/mage-expansion-v1/moth.gif)

## 盾は、実際に防いだ時に出る

既存の護身符板は、もともと敵の各段から2を軽減していました。命中イベントに記録された軽減量が正のときだけ、人物の後ろに半透明の盾面、前に明るい弧、六角の印と波紋を描きます。身体を横切る大きな白い閃光にはせず、敵を向く側に衝撃を集めました。護符を捨てた場合や攻撃がまだ届いていない場合は現れません。

![実際の二段攻撃。8ダメージと、法盾で合計4軽減した表示](screenshots/mage-expansion-v1/moth/mage-ward-hit.png)

これは従来の固定軽減を魔法らしく可視化したもので、独立した消耗式の盾HPはありません。鏡翼の蛾は6×2を撃ち、護符があると4×2が生命へ届きます。同じ冰矢・風刃の配置では護符ありの承傷32、護符を通常操作で捨てた場合は48で、どちらも9.50秒の勝利でした。実際の命中段数を使うため、一段目で倒れた時に二段目の盾衝撃を作りません。停止、倍速、戦前復元にも同じ時計とresetが効きます。

## 違う攻撃の二体

巡衛140生命・8単発/1.8秒に加え、鏡翼の蛾108生命・6×2/2.1秒と、荊棘の石像220生命・18単発/3.4秒を選べるようにしました。石像は攻撃1.1秒前から構え、蛾は宙に浮きます。いずれも準備時に選ぶ独立した一戦で、連戦の進行や報酬はまだありません。

![実機の石像戦。蒸汽と焰風を編み、法盾で重撃を受ける。無声6秒](screenshots/mage-expansion-v1/golem.gif)

敵二体と四つの道具図柄は内蔵imagegenで新規に作成しました。要求1536×1536に対して出力は各1254×1254です。[逐字提示](../../assets/art/mage-expansion-v1/prompts.json)と[寸法・alpha・取区・SHA-256](../../assets/art/mage-expansion-v1/manifest.json)を保存しました。元PNGは変更せず、敵はalpha 128以上の領域と共通倍率で描きます。部分透明や色数、人物原画と同じ論理格子の最終品質は未完成です。蛾の構え絵には月形の集光が含まれ、別のダメージイベントではありません。

描画上、浮遊した蛾の画像中心を命中点にすると翅へ着弾しました。四姿勢の核の位置をそれぞれ指定し、飛行の出発点と着弾点を合わせています。石像は足元、蛾は28px浮かせた位置を基準にし、三つの窓寸法で画面内の姿勢を検査しました。

## 四つの新しい組み合わせ

| 材料 | 魔法 | 基本値と占格 |
| --- | --- | --- |
| 水 + 微光 | 霜晶冰矢 | 9×1 / 1.8秒、1×2 |
| 風 + 微光 | 回旋風刃 | 4×2 / 1.4秒、2×1 |
| 火 + 水 | 蒸汽爆破 | 22×1 / 3.4秒、2×2 |
| 火 + 風 | 焰風涡旋 | 6×4 / 2.8秒、2×3 |

既存の焰爆と潮汐を合わせて六配方、基礎微光を含め七つの攻撃來源です。曲線、結晶の矢、風の弧、蒸汽、火と風の渦を分けました。名前は演出を表し、凍結・撃退・持続火傷・範囲攻撃は実装していません。晶核の各段+2や、材料・占格・回転・保存は既存の処理を通します。

水を左上の微光へ、風を左下の微光へ置く通常構築で蛾を9.50秒、承傷32で倒しました。石像の比較fixtureは最初の微光二つを通常操作で捨て、火＋水と火＋風を置き、中央晶核を双方へ接続します。蒸汽24×1と焰風8×4で12.10秒、承傷48でした。限られた材料を使った例で、バランス全体の結論ではありません。

新しい図鑑は上下の中心線に透明な余白がなく、単純に二等分すると下段の蒸汽と火の端が上段に入り込みました。alpha 128以上の空き行を測り、左y603、右y600で分けて修正しました。新しい四アイコンについて透明余白の検査も追加しました。元絵を切り貼りして描き直してはいません。

## 検証と保存

`game:classes:test` 623、`game:classes:art:test` 614、`game:mage:test` 62、`game:mage:vfx:test` 49、`game:mage:expansion:test` 142、`game:classes:feedback:render:test` 6、計**1496項目・失敗0**です。既知の異常指数保存テストは `Exponent too high` を二回出し、拒否と原子性の確認は成功しました。

新検査は六配方の両方向、材料不足や回転、四魔法の保存往復、敵の攻撃時刻と致死段数、盾あり/なし、停止・倍速、三窓サイズを対象にしました。実GPUで法盾の前後層だけを切り替えた差分は、三体とも戦闘画面外が0pixelです。巡衛の基準一戦は以前と同じ8.60秒・有効140・被害24、全統計が一致しました。三つのプレイヤー保存ファイルの指紋は変わっていません。

公開する27PNG・2GIF・8JSONと、原画3PNGの計40件を寸法・bytes・SHA-256で照合し、不一致0でした。42テキストのUTF-8と304ローカル参照も確認しました。GIF二本はそれぞれ39,840,768画素分のフレーム合成を独立デコーダで検証し、前フレームが残る描画誤りはありませんでした。これらの資料検査を1496項目へ重複加算していません。

旧形式の準備データは読み取れます。新しい魔法IDを含む保存を旧プログラムが読めるとは限らず、選択中の敵は保存せず次の起動時に巡衛へ戻ります。旧森林の949項目やC# buildは今回再実行していません。

画像は実際のGodot viewportで、素材の取得・編織・破棄は通常API、保存は無効にしたfixtureです。動画はMovie Makerの1440×960、固定24FPSから戦闘部分を原寸切出し、144枚・6秒をGIFへ量子化しました。差分透過で前フレームを保持し、デコーダで各画素の合成を検査しています。固定FPSは性能測定ではなく、無声映像です。[版別一覧](screenshots/mage-expansion-v1/manifest.json)には全画面PNGと二つのGIF、選択フィールドのみの撮影報告、検査報告を区別して保存します。
