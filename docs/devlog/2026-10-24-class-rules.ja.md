# 2026-10-24：二職業の資源・編織・一戦が動くC0原型

記録日：2026-10-24（JST）。今回は**独立したネイティブGodotの職業ルール原型**を実装しました。魔法使いの元素編織、騎士の重刃に一戦ずつ触れますが、C0全体の完了、C1の完成美術、二職業六構築の完成とは数えません。

## 動くようになったこと

新しい入口は次のコマンドです。

```powershell
npm run game:classes
```

魔法使いには無料で有限の火・水・風元素源があり、取得した原料も盤面を使います。火を基礎術式と組み合わせると2×2の焰爆法印、水と風は3×1の三段法術になります。原料を取得せず温存するか、配置を空けて能力へ変換するかを操作できます。戦前編織で材料を使い、戦中は冷却で再発動します。MP消費・元素返還はまだありません。

騎士は12ゴールドで有限の武装を買い、長剣と蓄勢徽記を合成して2×3の重刃にします。徽記を合成せず左右への支援として残す選択もあります。無料元素を取る魔法使いと、購入・鍛造する騎士の取得と準備を分けました。

共通部分は6×4、配置・回転・合成、方向支援と自動戦闘です。合成は完成品の全占有範囲を先に確認し、失敗なら材料・取得回数・ゴールド・UIDを変えません。支援物は左右、回転すると上下の実際の隣接セルに作用し、同じ支援物の利益を同じ攻撃物へ重複加算しません。

固定訓練相手と一戦し、実際の法術・武器ごとの有効ダメージ、発動数、命中数を表示します。戦闘は50msの整数ステップで、同時刻はプレイヤー行動が先です。停止・倍速・大きいフレームでも決まった順序を保ち、最初の致命打で終わります。演出が追加のダメージを決める構造にはしていません。

## コードと保存の境界

新しいカタログ、準備ルール、戦闘、保存、UI・盤面・示意場を `scripts/classes/` に分けました。細かい値とAPIの責務は[原型契約](../class-prototype-contract.md)、操作と現在の範囲は[実装範囲](../iteration-c0-rules.md)に記録しています。

現在の実験は魔法使い8件・騎士4件の物件、3配合、6取得元です。固定供給と固定敵で、保存する種子はランダム生成に使っていません。旧12装備・5配合・7祝福・5戦の森林サンプルは元の `npm run game` で遊べます。旧 `EmberRun` / `EmberSave`、主シーン、素材と既存保存は変更していません。

職業原型の保存先は `user://class-prototype-run.json`、文書種別は `class-prototype` です。新旧とも数字のschema 1を持ちますが、種別で分け、旧形式を職業へ変換しません。新しい版への実際の移行機能は未実装です。

検証するのは格位だけでなく、初期素材＋取得した素材＝持ち物の素材＋捨てた素材という一致、初期金額−実際の取得費＝残額、取得回数とnext_uidの一致です。64ビット種子は十進文字列で保存します。未知・損傷・将来形式、書き込み失敗や既存の復旧用一時ファイルがある場合は元ファイルを保ちます。保存できるのは満初期HPの準備で、一戦の前に検証・保存し、失敗時には開戦しません。

「戦前へ戻る」はそのままの取得回数と費用を戻す比較機能です。新職業の開始・読み込み時には前職業の一時戦前状態を消し、別の職業を復活させません。撮影と検証では保存を無効化するか `.tools/test-saves/` に専用ファイルを指定し、プレイヤーの既定ファイルを変えていないことも確認しました。

## 見つかった問題と修正

**ドラッグ中の回転。** レビューで、Rを押して盤面プレビューだけ回転し、落下時に古い方向を使う経路が見つかりました。Godotのドラッグ開始時の辞書と現在の選択が別だったためです。同じUIDまたは同じ取得元の操作に限り現在の方向を使うよう直し、実際のマウス入力による武器・購入物のドラッグで再確認しました。

**フォーカスと空白キー。** ネイティブButtonにフォーカスがあると、空白キーがそのボタンの操作になるため、訓練開始のキーをGUIの前で受けるようにしました。取得Buttonにフォーカスを残しても開戦することを確認しています。

**小さいウィンドウ。** 初期の縦方向の最小サイズでは1280×800に余裕がなかったため、画面高に応じて示意場と盤面の最小高を変え、長い取得/詳細列をスクロールにしました。フォントを全体縮小せず、実機の小窓でも控えと格位を見直しました。

**保存経路。** Windowsの末尾ドット・空白・代替データストリーム表記を拒否する境界を追加しました。既存の旧形式を守る内容検証に加え、ファイル名の別表記も受け付けません。実際に旧保存が破損したという記録ではありません。

**確認コマンド。** Controlスクリプトを直接 `--script` で起動した最初の確認は、SceneTree/MainLoopを継承していないため終了コード1でした。以降はPackedSceneを生成するUIテストと専用シーン入口で起動しています。
