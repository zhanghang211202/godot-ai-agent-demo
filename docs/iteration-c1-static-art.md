# C1 双职业静态美术样板

更新：2026-10-26（JST）。制作始于2026-10-25，26日完成本轮验证与记录。状态：**三张新绘静态人物与两套背景已接入可玩职业场景；动作与完整 C1 尚未完成**。本轮以用户选定的[MA 月庭礼装与 KA 旌旗长枪](character-baselines.md)为人物基准，把重新绘制的战斗姿态和各自背景接到可玩的职业场景；玩法仍以[C0 原型契约](class-prototype-contract.md)为准。

## 入口与本轮边界

```powershell
npm run game:classes
```

入口仍是原生 Godot 的 `scenes/class_lab.tscn`，继续通过项目内 `scripts/godot.mjs` 使用指定编辑器与本地 .NET 环境。默认 `npm run game` 保留 v0.3 森林样板、原规则与原存档；`npm run art:review` 保留六案人设比较，不是本轮可玩场景的替代入口。

本轮制作三张独立静态角色图：MA 持月杖、KA 持长剑、KA 持重刃。它们按已选人物重新构图，不从旧概念板切出所谓成品精灵。背景分别是法师的月庭／天文回廊与骑士的余烬圣堂，配合连续站立地面、脚底锚点和接触阴影，检查人物与 6×4 操作区的关系。

| 部分 | 本轮已接入 | 仍须独立完成的内容 |
| --- | --- | --- |
| 法师人物 | 保留紫红长发、琥珀眼、宽帽、层裙与月杖，使用专门绘制的战斗站姿 | 待机、施法、受击、退场逐帧动作；不同法术的专用姿势 |
| 骑士人物 | 保留 KA 的脸、栗色高马尾、象牙金甲与绯红衣料；按实际装备显示长剑或重刃姿态 | 长枪的正式持握／攻击与规则；盾反、连击路线及相应动作 |
| 两套舞台 | 独立职业背景、人物站位与连续地面，在真实窗口中显示 | 后续动画与多实体的遮挡、动态光效和更完整的环境制作 |
| 战斗和反馈 | 继续使用真实 C0 自动训练、来源事件、生命与结果；静态人物本身不驱动伤害 | 逐帧攻击／受击、角色移动及按动作同步的正式特效 |
| 其余表现 | 训练目标与背包文字物件保留明确的占位身份 | 专用敌人、物件图标、职业准备界面全量美术 |

这里的「静态」描述人物素材，不表示战斗是假图。场景仍可以取得元素或购买武装、整理格位、合成、开始训练并得到真实复盘；规则反馈线条或闪光也不算人物攻击动画。完整 C1 还需动作和视觉验收，不能因接入静态资源就勾选完成。

## 武器显示与规则的关系

KA 的长枪与旗帜继续作为已选人物的展示识别，但当前 C0 骑士从长剑起手，并可锻造誓约重刃。本轮为这两种已实现武器分别画姿态；保留 KA 的人物与衣甲，不换成 KC 的整个人设，也不把重刃伤害标签改成长枪攻击。

显示层根据准备阶段的实际战斗配置选择武器，进入战斗后使用该次战斗快照：有重刃时显示重刃姿态，否则有长剑时显示长剑姿态。骑士丢弃全部攻击武器时显示「待配武装」，不继续画出未持有的剑。读档、恢复战前和新开职业都应重新对应。法师的月杖保持人物识别，当前两种编织法术仍从真实来源事件显示。召唤、循环、盾反、连击与长枪机制没有因本轮美术接入而新增。

## 玩法与保存边界

法师仍有火／水／风各两份有限免费元素，骑士仍从 12 金币和有限武装中取舍。现有三条组合、6×4 摆放与旋转、方向支援、原子失败保护、固定训练敌人、暂停／倍速、来源复盘和战前恢复，继续按 C0 契约执行。具体入门组合与操作可见[C0 操作说明](iteration-c0-rules.md#入门操作)。

实验继续使用独立 `user://class-prototype-run.json`，读取和恢复只回到战前准备。没有把旧 `user://emberpack-run.json` 自动迁移为新职业；`EmberRun`／`EmberSave`、旧稳定物品 ID 与旧 12 装备／5 配方／7 祝福／5 战保持兼容。美术资源和显示状态不进入规则经济账本或存档格式。

角色的绘制源区取 alpha≥128 包围盒，包含人物和手持武器。三图分别为：

| 人物姿态 | 绘制源区 `(x,y,w,h)` | 1440×960 中的包围盒显示高度 |
| --- | --- | --- |
| MA 月杖 | `(55,59,1036,1311)` | 256px |
| KA 长剑 | `(78,113,1019,1207)` | 256px |
| KA 重刃 | `(137,125,957,1222)` | 256px |

1280×800 中三种姿态的包围盒显示高均为188px，1920×1080中均为256px。它们是**含武器的包围盒高度**，不能登记成人物头脚占高或独立逻辑画布。实际地面锚点、源区、显示矩形和倍率由运行报告记录；例如1440×960的MA源倍率约0.19527、KA重刃约0.20949，均为非整数。这里是等比最近邻的静态适配试验，源像素密度、有限色阶和逻辑网格仍待整理。

当前[静态资源缓存](../scripts/classes/class_art.gd)从项目内原 PNG 读取并缓存纹理，角色显示源区按 alpha≥128 的包围盒计算，避免微弱残留决定人物占高；原文件没有被裁切改写。[舞台绘制](../scripts/classes/class_arena.gd)按等比最近邻适配角色，背景以等比覆盖取景，另画连续前景地面。圣堂原图下沿含地砖立面，相机以源图高度86%处的石地为下边界，避免脚底落在立面上。`get_art_report()` 输出实际源区、显示范围、倍率、地面锚点、血条和训练目标范围；截图JSON的`visuals`只记录该fixture结束状态，不是每张截图各自的几何快照。独立导出包是否包含原 PNG 读取路径仍须另验。

## 实际观察与保留问题

- 1440×960下，MA的帽、月杖、眼神与发束可辨，KA的高马尾、白金甲、红披及双手重刃能够区分；人物脚底与连续地面相接，未被生命条或背包遮住。三图仍有细密金边和衣摆层次，较小显示中的细节取舍尚未完成。
- 背景按等比覆盖、下沿对齐。实际舞台主要露出下段柱廊、圣堂和地面，法师原背景上方的月亮、天文仪大多被裁；整张背景原图的景观不等于都出现在运行画面中。后续需按真实舞台宽高重新安排镜头与环境层次。
- 三张透明角色图含大量部分透明像素，边缘仍可见红／金等彩边；alpha≥128只决定绘制矩形，不会清理内部alpha或统一像素簇，不能作为生产级透明边缘通过的证据。
- 1280×800初版曾因固定行距导致「聚能晶核」跨出单格；已按字体ascent／descent和物件范围排版，小格装不下时显示短标签，完整名称和说明保留在悬停与详情中，支援方向双点移到边沿。舞台与完整6×4盘面均在窗口内，取得与详情以滚动容纳内容。1920×1080保留256px人物包围盒，并把更多空间分给操作区。文字物件、训练木靶和职业UI材质仍属后续美术工作。
- 这里只验证了开发机Windows原生运行。其他OS、DPI、显示设备、首次玩家试玩、性能与独立导出包未验；原PNG运行读取路径的打包行为也仍待专门检查。

## 完成标准与下一步

本轮交付可审查的静态画面：两名所选人物在各自背景、地面和真实职业操作布局中出现，武器对应当前构筑，现有一战和复盘仍能完成。对脸、发束、衣甲、握持、比例、源密度和三窗口遮挡的判断以实际显示为依据，不由提示词代替。

RV-03 的静态可读性证据可以在此积累，但不足部分仍需明确修正。RV-04 要求的真实逐帧动作，以及完整 C1 的双职业一战视觉切片，不由本轮静态候选代替。后续顺序是按实图整理人物与舞台，再制作待机／攻击或施法／受击／退场，之后扩充另外四条构筑、物件美术和教学。完整初期目标仍是两职业各至少三条构筑与五战流程。
