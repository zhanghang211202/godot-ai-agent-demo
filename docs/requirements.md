# ゲームの要件（仮題）

この文書は、以前の詳細な要件を現在の開発方針に合わせて日本語で整理したものです。**現在は魔法使い、敵、魔法の効果、道具と遊びの中心となる流れを優先します。** 騎士の新規開発と C2 は後回しです。[職業と構成](classes-and-builds.md) · [開発計画](development-plan.md) · [美術方針](art-direction.md)

## 目指すゲーム

道具を限られたマスに配置し、組み合わせて準備した結果が自動戦闘に表れる、オフラインの一人用 RPG です。基本は 6×4 の配置、回転、合成、方向による支援と自動戦闘です。題材は布のバッグに限らず、魔法使いなら術式を紡ぐ盤面、騎士なら武装を整える場所として表現できます。

将来的には、異なる職業、素材の集め方、戦い方、背景を持つキャラクターを増やします。初期候補は魔法使いと近接騎士で、各職業に少なくとも三つの構成を設けます。錬金術師は後の候補です。未実装の構想を現在の機能として扱いません。

## 現在の魔法使いの遠征

- `npm run game:mage` で七戦の遠征を起動します。旧保存の五戦と、`npm run game:mage:trial` の一戦は別のルールを保ちます。
- 戦前に限られた元素や道具を取得し、配置・回転・組み合わせを行います。配方は16種類です。実際の配置や合成を確定する前に資源を消費しません。
- 戦闘は自動です。術式ごとに発動し、動きと効果は実際の発射や命中に合わせます。複数の術式が同時に発動しても、それぞれの攻撃結果を保持します。
- 衛兵、蛾、石像、月灯、書霊、蛇、最後のボスの七体と順番に戦います。新しい敵の一部は一枚の姿勢を動かして表現しており、連続した身体の姿勢は未完成です。
- 勝利すると魔力の残滓を取得し、次の戦いの素材に変えられます。戦後は体力を回復し、配置と残り資源は引き継ぎます。敗北時はその戦いの準備へ戻れます。
- 実際に攻撃を軽減した時、魔法使いの周囲に法盾の効果を表示します。法盾は追加の体力ではありません。
- 月蛾、月冠蛾、風月蛾の契約は合計最大二体まで使い魔を呼べます。現在、敵は使い魔を攻撃せず、使い魔の独立した体力はありません。
- 遠征は専用ファイルに自動保存します。戦闘中の終了後は、その戦いの準備から再開します。保存失敗時は再試行を案内します。旧五戦の敵、報酬と資源のルールは維持します。

実際の七戦と保存の境界は[七戦の記録](devlog/2026-11-10-mage-seven-battles.ja.md)、プレイヤー向け画面は[画面の記録](devlog/2026-11-11-player-ui.ja.md)を参照してください。

## 操作と表示

配置できる範囲、回転後の占有マス、配方に必要な材料、残数と価格を分かるように示します。配置できない場合は道具や資源を失わず、配置前のプレビューは盤面や保存を変更しません。準備中の移動、回転、盤面内の合成は直前の一回を取り消せます。取得、破棄、開戦、読み込みなどでは取り消し履歴を消し、再起動後には保持しません。[取り消しの記録](devlog/2026-11-08-mage-undo.ja.md)

戦闘後は術式ごとの発動、命中、ダメージを確認できるようにし、プレイヤーに不要な内部 ID や開発用情報は表示しません。プレイヤー向けの画面と文章は、できるだけ簡単で自然な日本語を使います。

## 美術と動き

16-bit fantasy / tactical RPG を方向とする、顔、髪、服、革、金属、武器が読み取れる詳細なピクセル風の表現を目標にします。選択済みの魔法使い MA の外観と月庭を基準にし、敵の大きさと位置は種類に合わせます。[外観基準](character-baselines.md)

生成画像は手足、顔、武器の連続性、人物の同一性、切れや不要物を目視し、実際のゲームでも配置と動きを確認します。コンセプト画像を完成した戦闘素材や実機画面と扱いません。

魔法使いの動きには AnimationPlayer を使い、施法と実際のイベントを対応させます。中間姿勢や全身の傾きは、不自然に見えた試行を取り下げました。現在の見た目や流れは[アニメーション計画](ANIMATION_PLAN.md)を参照してください。

## 技術と互換性

- ゲーム本体は GDScript、Godot MCP のエディタープラグインは C# / .NET を使用します。SDK、npm とそのキャッシュはプロジェクト内に置きます。
- `EmberRun`、`EmberSave`、既存の道具 ID、旧森林版、旧職業実験と保存の互換性を保ちます。ユーザーの保存をテストで上書きしません。
- 新しい状態、敵の能力、職業や保存形式の変更は、表示上の名前だけで実装済みとせず、ルール、保存、テストを別に定義します。
- 実機画面と自動操作の試験画面を区別し、各版の画像を上書きせずに残します。実行していない環境や完成していない品質は、確認済みと書きません。

## まだ必要なこと

実際のプレイによる七戦の難しさ、構成の選択肢と資源量の評価、動きと魔法の見え方、敵の個性、音とエフェクトを継続して改善します。騎士の新規開発、職業ごとの三構成、奥術の循環、完全な召喚成長、錬金術師は将来の課題です。現在の配方数や固定条件でのテスト成功は、全構成の完成やバランス保証を意味しません。
