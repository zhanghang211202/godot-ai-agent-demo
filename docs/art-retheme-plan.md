## 1. 从单一换皮转为职业差异

不再要求用户从 A–H 中只选一个全游戏设定。首发角色分别具备身份、背景和物件语言，同时共享精细像素风格、中文原生排版、6×4 背包交互与自动战斗。法师吸收元素、组织法术或契约的获取流程不必套用全部购买装备；骑士可以通过遗物、锻造与战利品组织近战构筑；后续炼金术士可通过药水组合和自我强化建立不同决策。

这已经超出「12 件旧装备换名字」的纯美术范围。现有 **12 装备 / 5 异物配方 / 7 祝福 / 5 战**仍是 v0.3 实现事实，不等于新职业池，也不再作为禁止职业机制的理由。新资源、触发和获取规则必须经过 C0 定义及后续验证，不能由概念图中的 MP、连线或价格擅自引入。保留 `EmberRun` / `EmberSave`、旧物品稳定 ID 与合法旧档兼容；如需迁移，应有明确版本及测试。

新正式标题待定，「星火旅囊 / Emberpack」只保留为历史名称。内部兼容标识无需为了改名而全局替换。

不预设日历工期。先记录角色静态帧、动作和职业一战 slice 的实际生产与修正情况，再估剩余量；没有记录的时间不写入博客。

## 4. 三种人设造型与三种玩法流派分开验收

**每职业三种造型用于选择人设，每职业至少三种构筑用于玩法；两者不是同一个交付物。** 魔法师与骑士分别测试「简洁利落轮廓」「更明确衣甲层次」「更强器具/武器识别」等外观变体，保留各自身份与世界语言，不用三张外观图冒充三条玩法。

三案比较已提供全身概念、面部局部与静态缩小观察，用户选定MA＋KA。后续记录眼神、分束头发、布/皮革/金属、3.5–4.5 头身试验、持握、武器负形与脚底重心，保留双A已选的成年女性形象与衣甲器具方向；精确色值与专用武器帧继续制作验证。画布变大但角色仍由少量色块组成不能通过；高细节也不能牺牲实机辨识，现有比较不等于RV-02或RV-03完整通过。

大像素立绘与战斗 sprite 分别制作，共用一份角色设定表。不得把概念图切片当作生产精灵，也不得把立绘位移当作攻击动画。流派反馈依实际职业事件制作：例如召唤的来源和主体、重刃的蓄势与命中、格挡与反击次序；美术本身不能私自添加规则伤害。

## 5. 两种背景与统一背包交互

每个职业先制作一个独立主题区域的一段战斗背景，以远景、中景、地面分层。魔法师场景应给元素/法术留出空间；H 骑士场景强调圣堂遗迹与近战站立面。人物附近减少高对比碎纹，光源、建筑与特效避开脸、武器、名称、生命条和伤害数字。近景像素尺度与精灵一致，远景靠明度与饱和度退后。

两者共享低噪点的矩形 6×4 背包平面、占格/旋转/方向协同、合法/非法、合成与输入反馈，题材装饰集中在外框。获取面板则按职业组织：元素吸收不能只是把「购买」改成「吸收」却保留相同决策；遗物/锻造获取也需要与骑士流派实际相连。具体限制、代价与产出由 C0 规则表决定，界面准确显示它们。

首次接入至少检查 1280×800、1440×960、1920×1080。将源尺寸、人物实际占高、显示倍率、舞台范围和地面锚点记入清单；不把当前 512×144 森林当作不可改变的舞台约束。新角色放不下时先重新分配场景与留白，保持等比整数缩放与原生中文正文，再检查操作可达性。

首版静态试验实际源人物为1122×1402、背景2172×724，见[清单](../assets/art/c1-static-v1/manifest.json)。运行使用alpha≥128源区和等比最近邻非整数适配，原图不被改写；这是当前试验的例外，受控逻辑像素与整数倍率生产目标仍未通过。下一轮整理透明彩边、像素簇和色阶，并调整宽舞台的背景取景；不能把原图中的全部远景元素当作已在实机显示。

## 7. 主要风险与应对

| 风险 | 应对 |
| --- | --- |
| 只给旧装备换主题，被当成职业差异 | C0 明确获取、核心资源、触发链、成长与至少三条流派的不同决策，C1 分别跑通实际一战 |
| 两职业六流派同时量产导致失控 | C1 每职业只先一流派，验证接口与美术，再在 C2 扩展；炼金术士后置 |
| 概念图精致，实机退回简化小人 | 每职业真实窗口验收脸、头发、衣甲和武器；立绘和战斗精灵分别制作 |
| 像素画布增加但有效细节不足 | 检查人物占高、像素簇、透明边缘与整数倍率，不只看 PNG 数值 |
| 职业界面各自变化导致背包难学 | 统一网格、输入、落点、旋转和协同反馈，职业差异放在实际获取与规则 |
| 背景或多召唤物遮住主体 | 灰度审查、角色站位区留白、召唤物层级和数量表现按规则验证 |
| 新数据损坏旧档 | 保留旧稳定 ID 和兼容接口；新增职业 ID / 存档版本时显式测试读取或迁移 |
| 把八案、三造型与三流派混为范围承诺 | 文档分别列首发两职业、各职业造型比较、六流派玩法目标和后续题材储备 |
