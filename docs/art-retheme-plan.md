# 换设定与精细像素美术计划

日期：2026-10-23（JST）。状态：**待选题，尚未替换当前游戏**。本计划落实用户的最新要求，优先于原 M1-C 全量素材扩展；当前实现仍是[森林旅人 v0.3 样板](iteration-03-sample.md)。产品约束见[需求文档](requirements.md)，可执行视觉标准见[美术规格](art-direction.md)，候选 A–H 及概念配图见[美术与设定探索](art-style-exploration.md)。

## 1. 此轮要解决的问题

现有版本已经能验证布局、素材接口、旋转和自动战斗，但主角的脸、发型、衣装与武器细节仍不足以达到用户提供的 **16-bit fantasy / tactical RPG** 参考品质。仅补齐剩余旧规格图标不会解决角色吸引力，也会把尚未定案的背包世界观扩成更多返工。

因此先确定一个能同时解释人物、背景和格位器具的设定，制作达到精细像素要求的主角，再通过实际战斗画面确定尺寸和细节。新正式标题待选，不继续以「星火旅囊 / Emberpack」约束命名。所有候选统一像素画风，区别在题材、角色和色板；不把非像素成品或简化小人放回备选。

## 2. 保留的玩法与技术边界

| 保留内容 | 本轮允许变化 | 本轮不改变 |
| --- | --- | --- |
| 6×4 矩形构筑格 | 器具名称、槽位材质、外框、装饰 | 格数、矩形占格、碰撞、越界与命中规则 |
| 旋转与方向协同 | 端口、箭头、符路等题材表达 | 90° 整体旋转、实际受益格及原增益计算 |
| 同物升级与异物合成 | 物件名、剪影、材料汇聚和产物揭示 | 当前 12 物件 / 5 异物配方、结果与等级计算 |
| 自动战斗与成长 | 主角/敌人外观、场景、已有事件效果、奖励图标 | 当前 7 祝福 / 5 战、冷却、伤害、恢复、反伤和超时 |
| 现有保存与布局 | 通过资产映射和主题层接入新素材 | `EmberRun` / `EmberSave` 稳定 ID、旧档读取与 RNG 序列 |

旧 `backpack` 文件名与 `Ember*` 类名暂时作为内部兼容标识保留。玩家可见名称在题材选定后集中替换，避免为改标题而先做高风险的全局重命名。新职业、换装系统、法力条、月相循环、接线、游泳、新状态与敌人机制均不属于视觉换设定的隐含需求；M2 的规则工作维持原依赖。

## 3. 阶段、产物与退出条件

| 阶段 | 具体产物 | 退出条件 | 依赖与限制 |
| --- | --- | --- | --- |
| R0 选题 | A–H 的角色身份、背景、器具、色板、制作关注点与概念图比较 | 用户明确选择一个方向或说明组合方式；记录哪些元素保留、哪些排除 | 不能代替用户定案；名称是工作名；概念图不是游戏截图 |
| R1 主角定型 | 同一题材的三种主角造型、大像素全身立绘、脸/头发/衣甲/武器局部 | 用户认可方向；满足 RV-02 和主角静态六项要求 | 性别、发型、服装与配色在此阶段比较，不无意锁定；不同时扩多职业 |
| R2 尺寸与场景样板 | 专用战斗静态帧、一个背景/地面、同题材矩阵与三件基准物件 | RV-03 / RV-05：三种窗口能认出脸和武器，格位与操作可读 | 试验 96×128 / 128×160，不虚构参考源尺寸；先静态验证再做整套动画 |
| R3 一战接入 | 主角和一种普通敌人待机/攻击/受击/退场；已有事件驱动特效；整装和一战可玩 | RV-04 / RV-06：动作可区分、锚点稳定、旧档与既有规则回归通过 | 不用立绘位移替代动画，不靠视觉加入额外伤害 |
| R4 全量与交互 | 按新样板扩展剩余物件/祝福/敌人；教学、详情、比较、整装撤销 | 原 M1-C 的退出条件及全量美术要求满足 | 只在 R3 通过后恢复量产；每项区分新资产、旧占位与未做 |

不预设日历工期。先记录静态帧和一套动作的实际生产与修正情况，再估剩余量；没有记录的时间不写入博客。最终名称可以比题材稍晚定案，但 UI 的临时称呼和历史标题必须明确区分。

## 4. 主角的三种变体如何比较

三种变体应属于同一人设和世界，而不是把三个题材混成一张图。建议分别测试「简洁利落的轮廓」「更明确的衣甲层次」「更强的长武器或器具识别」，共同保留已选角色身份与色板。具体服装与性别由用户选择推进，不默认漂亮主角只对应某一性别。

每个变体提供相同姿势和展示比例的全身像素立绘、一张面部局部，以及相同战斗窗口中的静态缩放预览。记录脸与眼神、分束头发、布/皮革/金属、3.5–4.5 头身试验、手部持握、武器负形和脚底重心。画布大但身体仍由少量色块组成不能通过；高细节也不能牺牲实机辨识。

R1 的图片用于比较人设，R2 才验证生产 sprite 与窗口；两者都不宣称已有完整动作。概念图中的光影、装饰和格位仅表示意图，后续须按精确网格和资产清单重新制作。

## 5. 背景与界面样板

背景只制作一个主题区域的一个战斗段落，保持可复用的远景、中景和地面层；先让角色站得稳，再加景物。人物站位附近减少高对比碎纹，重要建筑与光源避开脸、武器、名称、生命条和伤害数字。近景像素尺度与战斗精灵一致，远景靠明度与饱和度退后。

矩阵内部保持低噪点的 6×4 平面；题材纹样集中在外框。攻击物、防御物、方向支援物各做一个基准：占格、完整旋转、方向端口、合法/非法和可合成提示必须与当前规则一致。商店与详情使用同套材质和色板，正文继续原生中文，不能为了精细角色而把文字缩小或遮住操作区。

首次接入至少检查 1280×800、1440×960、1920×1080。将源尺寸、人物实际占高、显示倍率、舞台范围、地面锚点记入清单；不把当前 512×144 森林尺寸当作不可改变的场景约束。若新角色放不下，应先重新分配场景与留白，保持等比整数缩放，再检查操作可达性。

## 6. 证据、素材和记录规则

- 概念稿存放 `docs/concepts/`，标注生成/制作方法、用途及「非实机」；本轮图像用于选题，不切片登记为已完成精灵。
- 用户两张本地参考图用于观察与图像生成的风格参考，公开授权与来源未确认，不随公开里程碑上传原图。概念图是原创设计探索，不能据此给参考原图补写许可。
- 新运行素材单独建立版本清单，登记稳定 ID 映射、实际 PNG 尺寸、帧、锚点、色板、哈希、来源和状态。新美术替换不能覆盖历史截图或虚构旧验收。
- 实机证据放入新的不可变版本目录 `docs/devlog/screenshots/`，保留 `v0.3-sample` 与更早版本。运行图、素材预览、概念图、fixture 各自标明；验证后记录实际提交。
- 各完成阶段更新日语开发日志和博客草稿，记录决定、真实问题、修复、检查数、未测项与限制；中文策划文档不被当成日语开发记录的替代品。
- 仅文档变更检查链接、格式和基线一致性；接入素材/布局运行相关资源和 UI 检查，修改规则或保存时才增加对应测试。检查数量不能代替人物品质审查。

## 7. 主要风险与应对

| 风险 | 应对 |
| --- | --- |
| 概念图精致，实机又退回简化小人 | R2 必须在真实窗口验收脸、头发、衣甲和武器；大立绘和战斗精灵分别制作 |
| 精细角色动画量过大 | 先完成一名主角、一种敌人和一战；按实际生产结果控制动作与变体，不提前量产全部角色 |
| 像素尺寸增加却仍然模糊 | 检查有效人物占高、像素簇、透明边缘与整数倍率，不只看画布数值 |
| 新器具让玩法难理解 | 6×4 平面、占格与方向提示优先；星盘不变圆格，符阵不靠装饰假装导通 |
| 背景抢走主角 | 局部明度/灰度审查，限制角色站位区纹理与特效，近中远景使用不同对比 |
| 改标题损坏规则 ID 或旧档 | 通过显示名/美术映射更新；保留内部稳定 ID，合法旧档与固定种子回归 |
| 候选被误读为正式定案 | 各文档与图注明确状态；只在用户选择后更新题材基线，工作名不冒充已核验正式名 |

## 8. 当前未决项

待用户选择：A–H 中的设定或明确组合；主角性别与身份气质；同题材三变体的取舍；最终标题。待实机确认：战斗源帧尺寸、人物占高、显示倍率、动作帧预算、色板及背景舞台尺寸。这些未决项不阻碍继续整理共同接口和选题图，但会阻止将任一候选直接量产并替换正式游戏。
