# C0 双职业首个规则原型契约

更新：2026-10-24（JST）。本页记录当前代码的实际行为；长期目标仍以[产品需求](requirements.md)、[职业与构筑设计](classes-and-builds.md)、[开发计划](development-plan.md)为准。以下数值是原型参数，不代表已完成平衡。

当前交付是独立运行的 **C0 首个规则原型**：魔法师 M-01 元素编织、骑士 K-01 重刃破阵各一条路线的固定来源一战实验。它只证明取得资源、空间整理、合成、自动战斗、来源复盘和战前保存的最小链条；**不代表 C0 所有退出条件完成，也不是 C1 精细美术切片或六路线完整 Demo**。

## 4. 格位、合成与方向支持

- 物件必须完整位于 6×4 内且不能重叠；旋转交换宽和高。元素也必须实体占格，没有场外无限库存。
- 可点击选择来源或背包物件，再点击格位放置，也可拖放；`R` 切换当前待放物件方向，`Esc` 取消选择。取消选择不消耗来源、金币或原料。
- 落在兼容配方物件上会立即合成，不经过额外确认弹窗。产物保留目标物件的 UID 与左上坐标，采用本次放置指定的方向。
- 合成先检查整个产物的占格，同时排除被消耗的两份输入；检查通过后才改变物件、扣费用或减少来源。越界、碰撞、不兼容、来源耗尽、金币不足和职业不符均无损失败，不留下隐形产物。
- 支持件默认向左右相邻边缘提供连接，旋转后改为上下。连接检查攻击物件的实际全部占格，不仅检查左上角；同一支持件对同一攻击物件只计一次。
- 聚能晶核与保留的蓄势徽记只强化本职业的攻击物件。每段伤害都加上支持值，护甲与未合成原料不获伤害加成。
- 舍弃立即移除物件，不返金币、来源份数或原料；成品被舍弃时，其全部基础成分进入 `discarded_materials` 账本。
- 战斗期间不能取得、移动、合成、舍弃或切换职业。战前配置可以恢复后重新训练，不发放新的补给。

## 5. 自动战斗与事件契约

双方对战固定的“训练守卫”：生命 **140**，每 **1.8 秒**攻击一次，原始伤害 **8**。敌人没有护甲、元素克制、召唤、破甲或其他状态。每个护甲物件提供固定护甲，护甲相加后减少每次敌方攻击，攻击伤害最低仍为 1。

战斗按 **50 ms 固定时间步、整数步序号**推进，首次准备时间和攻击间隔向上取整到该步长。首次命中在 `warmup` 后发生，后续按 `interval` 重复；本表中的时间均已落在步长上。多段法术的各段在同一步依次结算，尚未制作分段飞行延迟。

同一步先按配置中的攻击数组顺序执行玩家攻击，再处理敌人攻击；第一笔致命伤害立即结束战斗。相同时间的玩家致命一击会阻止该步的敌方攻击，不产生同时死亡。最多执行 1800 步，即 **90 秒**；第 1800 步的到期行动仍先结算，没有胜负才返回 `timeout`，界面归入训练失败。

暂停不推进规则时间；界面的 1× / 2× 仅改变传给规则层的时间量，动画与绘制不决定伤害。蓄势提示事件 `charge` 的伤害为 0；重刃实际释放事件为 `heavy_charge`。基础法术、爆发、多段和基础近战分别使用 `spell`、`spell_burst`、`spell_multi`、`attack`。

事件带递增 `event_id`、规则时间、来源 UID / 种类 / 名称、目标、类型与数值；伤害事件另带原始值，多段事件带 `hit_index`。事件用于驱动规则示意和复盘，并不表示已有正式角色动作。

复盘按来源 UID 汇总实际有效伤害、原始伤害、触发次数和实际结算命中数；总统计另记承伤、护甲减伤、溢出伤害和战斗时长。**有效伤害按剩余生命截断**，最后一击溢出不计入来源有效输出；致命一击之后未结算的段数也不计入命中次数。UI 目前呈现来源有效输出等主要数据，完整统计由战斗结果接口提供；尚未单独归因每件支持物或护甲物的贡献。

## 6. 独立战前存档

职业原型默认检查点是 `user://class-prototype-run.json`，文档标识为 **`kind="class-prototype"`、`schema_version=1`、`rules_version=1`**。这里的 schema 1 属于新原型自己的格式，与不含该 `kind` 的旧远征 schema 1 不相同；不能只看数字 1 就互相读取。

保存字段包含职业 ID、规范十进制字符串形式的 64 位种子、生命、金币、物件 UID / 种类 / 坐标 / 旋转、来源 ID / 种类 / 剩余次数 / 费用、`next_uid`、阶段以及舍弃材料账本。种子保存为字符串是为避免 JSON 数值精度丢失，不表示已经有 RNG 流程。

只接受 **`phase="prepare"` 且 `hp=max_hp=该职业初始生命`** 的检查点。当前不保存战中时间、冷却、事件队列或战斗结果，也不保存带伤的连续远征。正常实验入口在开战前先校验战斗配置并保存准备；保存失败则不进入战斗。读取检查点或“恢复战前”会从原配置重新开战，不从残余战斗时间继续。

读取先完成整个文档校验，再修改运行状态。校验内容包括职业与版本、各项类型和边界、所有物件所属职业、UID 唯一、完整占格不越界不重叠，以及每个来源 ID / 种类 / 固定费用与剩余数。资源账按以下关系精确相等，而非只检查“不超过上限”：

```text
初始背包基础成分 + 各来源已取得基础成分
    = 当前所有物件的基础成分 + discarded_materials

当前金币 = 初始金币 - Σ(每个来源已取得份数 × 固定单价)

next_uid = 初始物件数 + 所有成功取得份数 + 1
```

配方成品的 `materials` 定义保留其基础成分，因此不能伪造重刃或法术来绕过原料账。每次成功取得都会增加 `next_uid`，即使取得时直接合成并保留目标 UID；背包内移动合成和舍弃都不会增加该值。失败操作不增加值。

写入先验证快照，再写入和校验临时文件；覆盖既有合法原型时备份后替换。未知、损坏、不支持版本的既有文件不会被新局覆盖，发现已有 `.tmp` / `.bak` 恢复资料也会停止覆盖。重置接口只处理已验证的原型，并保留重置备份。单个存档读取上限为 65536 字节。

旧 `emberpack-run.json` 的文件名受到写入与重置保护。旧 schema 1 文档在职业入口会被识别为 `legacy` 并拒载，提示回到旧远征读取；原文件不被转换或改写。**本轮没有实现旧档向职业档迁移**，没有为旧装备分配法师或骑士身份。未知职业、未知格式和未来版本同样保留原文件并报错。

## 7. 仍需完成的目标

当前角色与背景只有明确标注的几何规则示意。大像素角色立绘、专门设计的战斗精灵、同职业三种造型比较、16-bit fantasy / tactical RPG 细节验收、独立正式背景与动作均待制作。原型物件的色块和文字也不是最终物件美术；概念板不能作为运行角色动画的交付证据。

完整初期目标仍是 **两职业 × 每职业至少三条路线，共至少六条可玩路线**，并有各自正常取得链和五战流程。本轮只实现元素编织、重刃破阵的首个一战原型；法师的契约召唤、奥术循环，骑士的盾誓反击、连击追猎四套机制均未实现，不能将三种法术或两把不同伤害的剑算成已经交付多条路线。炼金术士仍为后续职业。

C0 剩余工作包括其余机制的规则验证、六路线最小组件和来源预算、完整流程所需的资源与事件边界。C1 的双职业精细人物 / 背景 / UI 一战切片、C2 的六路线五战 Demo、C3 的教学、预览 / 撤销、平衡和发布也未由本原型完成。本原型的固定训练守卫与有限供给不能替代正式掉落、奖励、跨战资源或平衡验证。
