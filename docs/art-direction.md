# 星火旅囊：美术规格与提升计划

文档日期：2026-10-21。基线：已实现的 Demo v0.2；目标：v0.3 美术与交互升级。除明确标注“v0.2 现状”的内容外，下文均为需求提案，尚未制作或实现。画面与资产规格须先通过小范围样板验证，再成为批量制作标准。

本项目保持原创森林旅人题材。参考《靠装勇者：背包合成 RPG》的玩法可读性和成长反馈，不复刻其角色、图标、界面构图或原始素材。素材来源与许可证继续记录在 [asset-credits.md](asset-credits.md)。

## 1. 方向与目标

主题：青绿森林遗迹中的背包游侠。橘色围巾、象牙白斗篷、皮革旅囊是主角的识别特征；旧铜扣件、磨损布料、灯火与手写旅途记录构成界面的材质语言。整体温暖、清楚、有冒险感。

玩家首先看懂“这件装备占几格、能放哪里、与谁相连、能合成什么”，然后感受到装备变强与战斗获胜。背景丰富度不得压过装备、角色和合法放置提示。

v0.3 保持现有 12 种装备、7 种祝福、5 条特殊配方、6×4 背包和五场战斗规则。美术升级不额外加入装备技能、持续燃烧、职业、角色换装系统或新敌人机制。16 装备、9 祝福、8 配方属于 v0.4 的后续内容目标，不计入本轮资产验收。

## 3. 三项优先提升

1. **先统一像素密度与比例。** 角色等比显示，物品按占格制作专用剪影；场景、人物和界面图标使用可检验的源尺寸与整数缩放。先解决拉宽、拉长与画面颗粒不一致。
2. **让构筑反馈能直接看见。** 合成有材料汇聚和产物揭示；剑、箭、恢复、荆棘反击各有表现，装备触发与同一战斗事件同步。先制作主角和苔团的动作基准。
3. **建立旅囊界面的身份。** 背包用皮革、商店用陈列与灯火、手记用暖灰纸；主操作与次操作明确分级。材质只放在边框、页角和少量装饰处，装备与网格区域保持清楚。

## 4. 输出分辨率、布局与像素规则

### 4.1 分层布局提案

- UI 在实际输出分辨率布局，中文使用原生字体渲染；不再把整张 1440×960 界面连同文字统一缩放。
- 像素角色、装备、背景、特效使用最近邻采样和等比整数倍缩放。图形位置与缩放后的像素网格对齐；禁止双线性过滤、非等比伸缩和以模糊遮盖像素缺陷。
- 物品每格源尺寸为 32×32；默认每格显示 64×64，即 2 倍。可用宽高足够时允许每格 96×96，即 3 倍；先验证 1920×1080，再开放该档位。不能仅因窗口宽就切换，须同时容纳完整背包、正文和主要按钮。
- 默认 2 倍时，6×4 背包网格为 384×256，不含外框；3 倍时为 576×384。屏幕增加的空间用于留白、详情和战斗区域，不任意放大源图。
- 角色和场景在同一个战斗画布内采用相同源像素比例。战斗区域可以扩展可见范围或裁切远景；不把背景单独拉伸来填满面板。
- 明确区分“像素画”和“排版”：中文正文、数字、焦点框不需要被强制栅格化为低分辨率像素字体。

### 4.2 手工验收尺寸

| 输出尺寸 | 目标 |
| --- | --- |
| 1280×800 | 最小主要桌面目标；2 倍像素格。背包、购买、出售、详情与出发操作能完成一整轮，标题、正文不裁切 |
| 1440×960 | 主要制作与截图目标；默认 2 倍像素格，允许更舒展的留白和战斗区域 |
| 1920×1080 | 扩展目标；验证 3 倍像素格的可用布局，必要时仍保留 2 倍选项 |

低于 1280×800 时显示推荐窗口尺寸提示，并为次要信息提供滚动或折叠策略；不得通过挤压物品图形或缩小中文正文维持三列。具体降级布局在样板阶段验证，不承诺手机、任意比例窗口或所有 DPI 环境像素完美。记录实际窗口尺寸和 Windows 显示缩放；上述尺寸尚未完成手测。

## 5. 色板、材质与信息层级

以下为初始色板提案，样板通过后固定为 `ember_forest_v1`。主材质控制在约 24–32 个基础色，透明度与短暂特效不计入；不是把原有背景自动减色后视为完成。

| 用途 | 基准色 | 使用约束 |
| --- | --- | --- |
| 画面底色 / 最深阴影 | `#101B1C` / `#282731` | 不用纯黑填满大型内容面板 |
| 面板 / 皮革暗部 | `#18282A` / `#553A35` | 相邻面板通过明度、边缘和少量材质区别 |
| 皮革 / 铜件 | `#805342` / `#B67B50` / `#AD7D39` | 主要用于背包边缘、扣件、商店支架 |
| 正文 / 高光 | `#E8E6D2` / `#FFF2CE` | 正文优先可读，稀有装备高光不得占满区域 |
| 辅助文字 | `#A8BBB0` | 小字不使用过暗的低对比灰绿；实测对比后调整 |
| 主操作 / 合成 | `#E4BD76` | 金色保留给出发、确认、可合成与重要成长 |
| 合法放置 / 恢复 | `#83C6AD` | 合法放置同时有边框或勾形，不只靠颜色 |
| 方向支持 | `#8DCBEA` | 蓝色箭头、节点与连接关系，区别于普遍选中态 |
| 错误 / 敌方伤害 | `#E78D82` | 使用叉形、说明或数字前缀，避免只凭红绿辨认 |
| 围巾 / 火焰 | `#DF7C43` / `#FFC56C` | 主角识别点和瞬时火焰效果，不改变规则含义 |

统一左上光源；角色与物件用 1 源像素主轮廓和不超过三档的单材质明暗。地面阴影与脚底锚点一致；远景不套同样强的黑轮廓。背景中的角色站位区降低局部对比和细碎高光。

UI 信息优先级为：可执行主操作 → 物品与放置结果 → 生命、金币、战斗状态 → 名称和详细解释 → 场景装饰。中文正文以实际输出像素 16 px 为起点，辅助文字不低于 14 px，标题约 22–28 px；样板时按字体度量验证换行，不能把缩小文字当作处理溢出的常规方案。

## 6. 角色与敌人规格

常规角色帧画布 64×64，可保留透明留白；脚底锚点统一为 `(32, 58)`。树形强敌使用 96×96，脚底锚点 `(48, 88)`。这些是新资产画布尺寸，不是 v0.2 角色当前尺寸。

| 资源 ID | 形象与辨识 | 本轮范围 |
| --- | --- | --- |
| `hero` | 橘围巾、象牙斗篷、皮革旅囊；清晰的头、手、脚层次 | 先做样板；固定旅人形象，不实现逐件穿戴换装 |
| `slime` | 苔团，偏圆的轮廓、叶片或苔点；柔软压缩和回弹 | 与主角一起验证战斗节奏 |
| `wolf` | 暮林狼，低重心、长口鼻、明确前后腿 | 样板通过后扩充 |
| `goblin` | 苔刃哥布林，矮身、尖耳、破旧短刃 | 样板通过后扩充 |
| `tree` | 树形强敌，树根脚、枝臂、遗迹纹样 | 96×96；树卫、树王共享基础动作，以树冠、胸口火光和配色区分两场，不新增规则 |

每类先按以下最小动作预算制作；动作表现可在不增加规则的前提下调整：

| 动作 | 帧数 | 初始节奏 | 约束 |
| --- | --- | --- | --- |
| 待机 `idle` | 4 | 每帧约 150 ms，循环 | 呼吸或形变，不用整张图周期性上下漂浮代替 |
| 攻击 `attack` | 4 | 每帧约 75 ms，一次 | 命中姿态与事件对齐；完成后回到待机 |
| 受击 `hurt` | 2 | 每帧约 80 ms，一次 | 可配短闪色；不中断或修改规则计算 |
| 退场 `defeat` | 4 | 每帧约 110 ms，一次 | 能分辨击败与普通受击，结束姿态不遮挡后续弹层 |

五类基础视觉共 70 帧；主角与苔团样板为其中 28 帧。树卫、树王的外观变体不作为两套全新动作预算。角色素材朝向统一，敌我需要反向时只做完整精灵水平翻转并复核非对称特征；不缩放某一轴。

战斗表现不能要求每件装备都改变主角外观。先由武器来源触发斩击或箭矢表现；固定持剑的角色图不能在弓单独攻击时继续显示通用近战斩击。可采用中性持械姿态配武器效果解决，具体设计在样板中确定。

Ⅰ、Ⅱ、Ⅲ级继续沿用现有规则。级别以角标、边框和少量高光区别，不要求为每件装备绘制三套造型；选中、稀有度、可合成必须使用不同标识组合。

## 8. 森林场景与界面材质

新森林分为远景、中景、地面/少量前景三层：

1. 远景使用低对比雾色、山线与树冠，减少尖锐高光。
2. 中景保留遗迹石柱、灯火和主树，避开名称、生命条与飘字区域。
3. 地面提供连续站立基线，角色脚下有接触阴影；少量蕨叶可以在侧边，但不挡角色身体和物品特效。

背景源图尺寸按样板的战斗画布确定并登记，宽高取整数像素；不要把历史背景 1983×793 当成新规范。先制作一套森林，暂不加入第二章场景、天气和复杂视差系统；分层首先用于控制遮挡和可读性。

背包边缘可有皮革、缝线和铜扣，内部网格保持低噪点。商店使用木架或布垫边缘，不在每张物品卡内重复一幅复杂插画。手记采用暖灰纸底、墨绿色正文，先验证文字对比后再增加纸纹。装饰不能侵占拖动命中区域。

## 9. 交互、战斗与声音反馈

| 场景 | 视觉与反馈要求 |
| --- | --- |
| 悬停 / 选中 | 悬停为轻微提亮；选中为稳定角标或轮廓，不与合成金框混同 |
| 拖动 | 保留源位置淡影；目标占格清楚；光标附近提示旋转与取消 |
| 合法 / 非法放置 | 合法为青绿边与格面；非法为红边、叉形或简短原因；均不只靠颜色 |
| 方向协同 | 蓝色节点配方向箭头；悬停支持物时突出实际生效格，显示受到强化的武器 |
| 可合成 | 显示产物剪影、最终占格和名称；空间不足显示原因，不显示成功金色提示 |
| 合成完成 | 材料短暂汇聚、产物揭示、一次提示音；不长时间阻断连续整理 |
| 武器触发 | 来源装备冷却完成与闪光一致；剑显示斩击，弓显示箭矢，火焰剑使用火色斩击 |
| 命中 / 暴击 | 伤害、受击和命中特效来自同一规则事件；暴击通过字样、字号和形状区分 |
| 恢复 / 反伤 | 恢复为向上的叶光或水滴；反伤为短促荆棘冲击，明确来源与受伤目标 |
| 弹层 | 遮罩覆盖整个输出区域，底层按钮视觉禁用；明确焦点、确认与返回操作 |

特效预算八类：斩击、火焰斩击、箭矢、普通命中、暴击强调、恢复、荆棘反击、合成。每类采用短动画或有限粒子，不依靠全屏闪白。静音状态保留全部关键视觉反馈。

模拟伤害不得为了动画而延迟、重算或漏掉。可以让攻击首帧处于命中姿态，或由现有冷却提前展示准备动作；事件到达时，伤害数字和受击表现必须同步。多武器同时触发时应避免飘字完全重叠，不能通过删除规则事件解决画面拥挤。

声音本轮只要求功能区别：拿起/放下、购买、合成成功、非法操作、普通命中、恢复、胜负。不采购或搬运参考游戏音频；具体自制或许可来源另行登记。动画与声音不得成为新增游戏机制的依据。

## 11. 制作顺序与验收门槛

### 样板阶段：先验证，再批量制作

制作主角、苔团、短剑、圆盾、磨刀石和一屏 UI；其余沿用旧资源并在记录中标明。形成整备、拖动、合成预览、战斗和祝福卡片布局五种状态。样板通过后，按相同规范制作剩余角色、12 件装备全量和 7 个祝福；仍不扩充规则数量。

### 可执行验收

以下 VA 为全量目标；M1-B 样板只对该阶段的英雄、苔团、三件装备、已接入反馈及可达界面验收，M1-C 才核验 12 件装备、全角色和全状态。未制作的全量资产必须标为未验，不能以样板通过代替。

1. **VA-01 尺寸与比例**：清单和 PNG 尺寸一致；64×64 角色、96×96 树形、32 px 物品格符合规格。所有素材等比显示，长条装备不存在方图拉伸；完整旋转前后占格和命中范围一致。
2. **VA-02 像素与边缘**：2 倍与允许的 3 倍档位下检查局部截图，源像素大小稳定，无双线性模糊、透明白边或不规则跳像素。UI 正文独立保持原生清晰度。
3. **VA-03 构筑可读性**：12 件装备在缩略图和背包中各有不同轮廓；去掉名称时仍可按图鉴配对。合法、非法、选中、可合成、方向协同可由形状或文字区分，灰度下不完全丢失关键状态。
4. **VA-04 角色与动作**：主角围巾/斗篷/旅囊可辨；脚底锚点稳定。每类具有规定动作，树卫与树王有明确外观区别；不要求两套新规则。实际跑一场战斗检查同帧事件表现，不能仅凭静态截图判定通过。
5. **VA-05 文字与布局**：1280×800、1440×960 完成一次购买、旋转、合成、出售、战斗、祝福和菜单流程；1920×1080检查扩展。无文本溢出、按钮重叠、重要内容不可达；记录显示缩放和实际档位。
6. **VA-06 反馈正确**：弓不触发近战斩击；恢复、反伤、暴击与来源一致；火焰剑不播放会使人误认为已有持续燃烧的额外伤害跳字。静音后仍看得懂操作结果。
7. **VA-07 弹层与性能**：遮罩覆盖完整输出；底层交互禁用与焦点正确。实机验证战斗和密集整理没有持续卡顿，记录机器、窗口尺寸和实际测量；未经测量不写固定帧率承诺。
8. **VA-08 回归与证据**：运行与改动相关的现有规则、存档和 UI 检查；美术升级不能改变旧存档中的物品 ID、占格或规则结果。实机截图留存至 `docs/devlog/screenshots/v0.3/`，至少包含整备、拖动预览、战斗、合成与祝福；开发过程和真实限制以日语记录。版本目录建成后不覆盖 v0.2 图片。

完成定义是：样板和全量资产各自有审查记录，目标尺寸的实际流程通过，运行截图与实现一致，并在素材清单中区分完成项和保留的旧素材。当前文档完成不等于以上验收已通过。
